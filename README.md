# positive-judge

形態素解析(janome)と日本語評価極性辞書を使って、日本語の文がポジティブかネガティブかを判定する小さなツールです。

## 判定の流れ

1. 形態素解析で文を単語に分け、基本形(原形)に直す(「楽しかっ」→「楽しい」)
2. 感情辞書と照合して、各語に +1 / -1 を付ける
3. 同じ節にある「ない」「ません」などの否定で極性を反転する(二重否定は元に戻す)
4. 逆接(「けど」「のに」「が」)の後ろの語は2倍の重みで数える
5. 合計スコアで ポジティブ / ネガティブ / 混在 / 判定不能 を出す
6. ポジティブな表現があっても、ネガティブな出来事に似ている場合や、ネガティブな出来事の節のあとにポジティブな節が続く場合は、**皮肉の可能性あり**とする(下の「皮肉の検出」)

## ダウンロードして使う(インストール不要・Windows / Mac / Linux)

このリポジトリの「Releases」から、使っているOSのファイルをダウンロードします。同じ場所の `SHA256-*.txt` と、ダウンロードしたファイルのハッシュ値(Windows: `Get-FileHash ファイル名`)が同じなら、改ざんされていません。
形態素解析器も感情辞書も、ファイルの中に入っているので、**何もインストールせず、インターネットにつながなくても動きます**。

| OS | ファイル | 使い方 |
|---|---|---|
| Windows | `positive-judge-windows.exe` | ダブルクリックで起動 |
| Mac(Apple シリコン) | `positive-judge-macos.tar.gz` | 展開して、ターミナルから実行 |
| Linux | `positive-judge-linux.tar.gz` | 展開して、ターミナルから実行 |

起動したら、判定したい文を入力して Enter を押します。(何も入力せず Enter で終了)

**Windows**
- 「Windows によって PC が保護されました」と表示されたら、「詳細情報」→「実行」を選びます。署名のない exe では表示されることがあります。
- コマンドからも使えます: `.\positive-judge-windows.exe "今日はとても楽しかった!"`

**Mac / Linux**
```
tar -xzf positive-judge-macos.tar.gz     # Linux は positive-judge-linux.tar.gz
./positive-judge "今日はとても楽しかった!"
```
- Mac で「開発元を検証できません」と表示されたら、一度だけ次を実行してから、もう一度起動します。
  ```
  xattr -d com.apple.quarantine ./positive-judge
  ```
- Intel の Mac 用のファイルは用意していません。Intel の Mac では、下の「インストール(1行)」を使ってください。

```

ソースを取得して使う場合は、次のとおりです。

```

### 日本語評価極性辞書

辞書を指定しなければ、日本語評価極性辞書(東北大学 乾・岡崎研究室)を**初回に自動で取得**して使います。
辞書本体はこのリポジトリに含めていません。`~/.cache/positive_judge/` に保存し、2回目以降は保存したものを使います。
取得できないとき(オフラインなど)は、警告を出して内蔵の小さな辞書だけで判定します。

別の辞書を使う場合や、自動取得を止める場合は、次のようにします。

```
positive-judge --dict-url <辞書のURL> -f sentences.txt   # 指定した辞書だけを使う
positive-judge --dict 自作辞書.tsv "..."                   # 手元のファイルを使う
positive-judge --no-default-dict "..."                      # 内蔵の辞書だけを使う
```

### オプション

| オプション | 内容 |
|---|---|
| `--no-default-dict` | 既定の辞書の自動取得をしない(内蔵辞書だけを使う) |
| `--dict-url URL` | Webの感情辞書を取得して使う(複数可。指定すると既定の辞書は使わない) |
| `--dict FILE` | ローカルの辞書ファイルを使う(複数可。zip / tar.gz 可) |
| `--user-words FILE` | 自分の言葉の辞書を足す(複数可)。辞書にない言葉(俗語・業界用語など)用 |
| `--no-slang` | 内蔵の俗語・口語の辞書(きもい・エモい など)を使わない |
| `--suggest-words FILE` | 文章のファイル(1行1文)から、辞書にない言葉の候補を集めて保存して終了する |
| `--suggest-out FILE` | `--suggest-words` の保存先(既定 `words_to_review.tsv`) |
| `--ignore 語` | 判定から外す語(複数可。例: `--ignore サービス`) |
| `--contrast-weight N` | 逆接の後ろの重み(既定 2、`1` で無効) |
| `--sarcasm MODE` | 皮肉の扱い。`flag`=「皮肉の可能性あり」と表示(既定) / `negative`=ネガティブとして扱う / `off`=検出しない |
| `--events FILE` | ネガティブな出来事のファイルを追加する(複数可) |
| `--no-seed-events` | 内蔵の出来事の見本を使わない |
| `--no-contrast-rule` | 「ネガティブな出来事の節のあとにポジティブな節」というルールを使わない |
| `--event-threshold X` | 皮肉と疑う類似度のしきい値(既定 0.7。仮の値) |
| `--learn-events FILE` | 文章のファイル(1行1文)から、ネガティブな出来事を集めて保存して終了する |
| `--events-out FILE` | `--learn-events` の保存先(既定 `events_learned.txt`) |
| `--min-score X` | 数値スコア付き辞書で、絶対値がX未満の語を無視(既定 0.5) |
| `--backend` | `auto` / `fugashi` / `janome` / `sudachi` / `builtin` |
| `-v` | 形態素の一覧も表示 |

## 皮肉の検出

辞書だけで判定すると、皮肉の中のポジティブな語が拾われて、皮肉がポジティブと判定されてしまいます。

> 一人で文化祭まわるの確定しました。**ありがとう!** → 辞書だけでは「ポジティブ」

皮肉は、**ネガティブな出来事のあとに、ポジティブな表現が来る**という対比を持ちます。
そこで、ネガティブな出来事のデータベースを持ち、入力がそれに似ていて、かつポジティブな表現があるときは、「皮肉の可能性あり」と表示します。

```
結果: 皮肉の可能性あり  (表面の判定: ポジティブ / スコア +1 / ポジ語 1・ネガ語 0)
  + ありがとう
  ※ 皮肉の根拠: ネガティブな出来事「一人 文化祭 まわる 確定」に似ている(類似度 1.00)
```

- `--sarcasm negative` にすると、「ネガティブ(皮肉の可能性)」として扱います。`--sarcasm off` で、検出を止められます。
- 「(皮肉)」「棒読み」という表現がある場合も、皮肉の可能性として扱います。
- 内蔵の出来事は、12件の**見本**だけです。実際に使うときは、自分の文章から集めたものを使ってください。

### 対比ルール(状況の節と評価の節)

文を、「。」「、」や接続の語で節に分けます。**ネガティブな出来事の節**のあとに**ポジティブな節**が続いていて、間に逆接(けど・が・のに・でも・しかし)がなければ、皮肉の可能性ありとします。

```
満員電車で足を踏まれた。朝から気分爽快だよ。   → 皮肉の可能性(出来事のあとにポジティブ)
待ち時間は長かったけど、おいしかった。          → 皮肉ではない(逆接でつながっている)
```

ネガティブな出来事の節かどうかは、辞書のネガティブな語、または出来事の見本との類似で決めます。辞書にない出来事は、見逃します。
これは、鈴木 翔太の修士論文(Bharti らの situation phrase / sentiment phrase の考え方を日本語のレビューに適用)を、簡易化したものです。論文は、係り受け解析で文節に分け、品詞の組み合わせで「状況」と「評価」に分けています。ここでは、句読点と接続の語で節に分けています。
論文の報告では、皮肉の多いゲームのレビュー139件で F値 0.68(適合率 約0.75、再現率 約0.63)、通常のレビュー60件では F値 0.52 でした。**日本語のレビューでの結果であり、このツールの精度ではありません。**

### 出来事を集める

文章のファイル(1行1文、UTF-8)から、「**出来事 + 接続表現(から・ので・ため・て・のが・のは・ことが・ことは・ことを・ことに)+ ネガティブな感情表現**」の形の文を探して、出来事を取り出します。
ネガティブな感情表現が否定されている場合(「疲れなかった」など)は、除きます。

```
positive-judge --learn-events tweets.txt --events-out events.txt     # 集める
positive-judge --events events.txt "待ち時間が長いけど、最高のサービスですね"   # 使う
```

### 論文との違い、限界

この機能は、次の論文の考え方を取り入れたものです。ただし、**簡易化**しています。

- 論文は、類似度を「単語の分散表現による距離(WMD)」で求め、さらに SVM で皮肉かどうかを学習します。ここでは、**単語の重なりの割合**と、**しきい値**で判定します。しきい値(既定 0.7)は仮の値です。
- 論文は、約47,000件の出来事を、1億語以上のコーパスから集めています。ここでは、自分のデータから集める仕組みだけを用意しています。
- 論文は、係り受け解析で出来事を切り出しています。ここでは、語の並びで近似しています。
- 論文自身の結果でも、効果は「わずか」です(未知のデータでの F値: 提案手法 0.657、比較手法 0.658)。**皮肉を確実に見分けられるわけではありません**。
- 出来事に似た語があるだけで、「疑い」が出ることがあります(例:「待ち時間が長かったけど、楽しかった」)。あくまで目印として使い、最終的な判断は、実データでの確認をしてからにしてください。
- 判定では、ポジティブな評価表現(「最高」「ありがとう」など)を除いた「状況」の部分だけでも、出来事との類似を見ます。
  これは、2023年人工知能学会全国大会の論文(畑ら、関西大学。皮肉の対象が書かれていない文を、BERT で「皮肉な状況」として分類する研究。正解率は 0.867 と 0.788 と報告)の考え方に沿った簡易版です。
  この論文の BERT 分類そのものは入れていません(学習データとモデルが必要なため)。代わりに、上の `--classifier` でつなげるようにしました。
- 形態素解析器(janome)が入っていない簡易モードでは、出来事の語が細かく割れて、うまく動きません。

### 辞書にない言葉(俗語・口語)を判定する

東北大学の辞書には、「きもい」「エモい」「むかつく」のような、新しい言い方や口語がほとんど入っていません。次の3つで補います。

**1. 内蔵の俗語辞書**(何もしなくても効きます)
`positive_judge.py` の `SLANG` に、約90語を入れています(作者が書いた見本で、網羅的ではありません)。
「きもい」「キモい」「きもかった」「キモくない」のような、ひらがな・カタカナ・活用の違いは、同じ語として扱います。
形態素解析器が語を細かく割っても(き|も|かっ|た)、1つの語にまとめてから判定します。使いたくない場合は `--no-slang` です。

**2. 自分の言葉を足す**(`--user-words`)
1行1語のファイルを作ります(UTF-8)。タブか空白で区切ります。

```
# 語   極性(p か n)   種類(形容詞 / 五段 / 一段 / なし。省略可)
バグる   n   五段
エグい   n
ネトゲ廃人   n
```

```
positive-judge --user-words mywords.txt "スマホがバグってつらい"
```

種類を省略すると、かなだけで「い」で終わる語は形容詞、それ以外は活用しない語として扱います。

**3. 辞書にない言葉を、自動で探す**(`--suggest-words`)
自分のアプリの文章(1行1文)から、辞書にない言葉の候補を集めます。

```
positive-judge --suggest-words tweets.txt --suggest-out words_to_review.tsv
```

保存されたファイルには、語・出現数・ポジティブ寄りの文の数・ネガティブ寄りの文の数が入っています。
開いて、`?` を `p` か `n` に直し、要らない行を消してから、`--user-words` で使います。
**極性は、自動では決めません**(同じ文にある既知の感情語は、手がかりにすぎないためです)。人が確認してください。形態素解析器(janome)が入っていないと、語が細かく割れて、候補が不正確になります。

`python evaluate.py` で、`data/slang_check.csv`(40文)の正解率を、俗語の辞書あり・なしで比べられます。作者が書いた文での確認です。

### 他のアプリから使う(JSON)

```
positive-judge --json "待ち時間が長いけど、最高のサービスですね"
```

1行1件の JSON(`label` / `score` / `sarcasm` / `reasons` / `hits`)を標準出力に出します。状況メッセージは標準エラーに出ます。
Python から直接使うときは、`positive_judge.analyze(text, tokenize, polarity, 2, sarcasm)` が同じ内容の辞書を返します。
Swift・Kotlin に移すときは、この JSON の形を「正解」として、同じ入力で同じ結果になるか確かめてください。

### 学習済みモデル(BERT など)をつなぐ

皮肉かどうかを学習したモデルがあれば、`--classifier モジュール:関数` でつなげます。関数は、文字列を受け取り、0〜1 の「皮肉らしさ」を返します。
0.5 以上なら、皮肉の根拠に加わります。モデル本体は、このリポジトリには入っていません。

```python
# mymodel.py
def predict(text: str) -> float:
    ...  # 自分で学習したモデルの確率を返す
```

```
positive-judge --classifier mymodel:predict "一人で文化祭まわるの確定しました。ありがとう!"
```

### 評価する

```
python evaluate.py --errors
```

`data/sarcasm_eval.csv`(皮肉 100 件・皮肉でない 100 件)で、適合率・再現率・F値を出します。しきい値は dev で選び、test で評価します。
**このデータは作者(Claude)が書いた合成データです。** 実際の SNS や会話の文ではなく、皮肉の書き方にも偏りがあるため、数値は実データより良く出ます。
仕組みの確認としきい値の目安に使い、本番の精度の根拠にはしないでください。実際のアプリでは、実データで必ず測り直してください。
`data/events_corpus.txt` は、出来事を集める用の合成文章です(評価データとは別)。

## 限界

- 単語単位の判定です。皮肉や、文脈が必要な文は正しく判定できないことがあります。
- 辞書にない語は拾えません。
- スコアは極性語の個数(重み付き)の合計で、語ごとの強さは考慮しません。
- 辞書の語自体が極性を持つため、「サービス」「友達」のような語で加点されることがあります(`--ignore` で外せます)。
- 解析器が入っていない環境では、内蔵の簡易トークナイザーで動きますが、精度は大きく下がります。
- 皮肉の検出は、目印を出すだけです。出来事のデータベースにない皮肉は、見逃します。上の「皮肉の検出」を参照してください。
